# Как запустить и показать проект

В Compose запускаются шесть контейнеров приложения. Prometheus и Grafana
включаются дополнительно. Веб-интерфейс, вход и ПТО доступны через один адрес:
`http://localhost:8080`.

## Первый запуск

Откройте PowerShell в папке проекта `C:\Users\User\smart_factory`.
Убедитесь, что запущен Docker Desktop и команда `docker info` работает.

Проверьте, что в корневом `.env` задан `PTO_ACCESS_PASSWORD`. Файл `.env`
исключён из Git; пароль не нужно показывать в демонстрации.

Создайте отдельную копию базы SQLite для контейнера:

```powershell
.\.venv\Scripts\python.exe .\scripts\prepare_compose_data.py
```

Скрипт читает `data\maintenance.db` через SQLite backup API и создаёт
`data\local\compose\maintenance.db`. Исходная база остаётся для обычного
локального запуска; существующая Compose-копия повторно не перезаписывается.

Соберите и запустите стенд:

```powershell
docker compose config --quiet
docker compose --parallel 2 up --build -d --wait
docker compose ps
```

Первый запуск скачивает базовые образы и зависимости, поэтому может занять
несколько минут. Продолжайте, когда все шесть сервисов имеют состояние
`healthy`. Затем откройте `http://localhost:8080` и войдите с логином и
паролем из `.env`. Если порт 8080 уже занят, задайте в `.env` другой
`FRONTEND_PORT`, например `8087`, и используйте `http://localhost:8087`.

## План короткой демонстрации

1. В PowerShell покажите `docker compose ps`: запущены отдельные frontend,
   catalog, telemetry, production, simulator и maintenance.
2. Откройте браузер и покажите вход, главную и страницы мониторинга датчиков,
   выпуска и планово-технического обслуживания. Всё открывается на одном
   локальном адресе.
3. На мониторинге покажите поступающие учебные показания. Симулятор создаёт
   синтетические данные; это не подключение к реальному оборудованию.
4. В ПТО покажите список оборудования и график обслуживания из скопированной
   SQLite-базы. Входные данные контейнера хранятся отдельно от исходной базы.
5. При необходимости покажите `docker compose logs --tail 50 simulator` и
   объясните связь сервисов по DNS-именам во внутренней Docker-сети.
6. Можно показать работу от непривилегированного пользователя:

   ```powershell
   docker compose exec maintenance python -c "import os; print('uid:', os.getuid())"
   ```

   Ожидаемый UID — `10001`.

## Prometheus и Grafana

Для этой дополнительной демонстрации задайте собственный сильный
`GRAFANA_ADMIN_PASSWORD` в локальном `.env`, затем выполните:

```powershell
docker compose --profile observability up --build -d --wait
```

Prometheus откроется на `http://localhost:9090`, Grafana — на
`http://localhost:3000`. Имя пользователя Grafana по умолчанию `admin`.
Порты доступны только на этом компьютере.

## Остановка и следующий запуск

Остановить контейнеры, сохранив их, можно так:

```powershell
docker compose stop
```

Запустить их снова:

```powershell
docker compose start
```

`docker compose down` удаляет контейнеры и сеть, но сохраняет SQLite-копию и
тома Prometheus/Grafana. Не добавляйте `-v`: он удалит историю мониторинга.

## Границы этого этапа

- ПТО пока хранит данные в SQLite; переход на PostgreSQL, миграции и проверка
  восстановления резервной копии запланированы отдельно.
- У КТП пока нет самостоятельного сервиса. Заявки производства и показания
  датчиков хранятся в памяти и сбрасываются при пересоздании их контейнеров.
- Контейнеры используют непривилегированных пользователей, проверки
  готовности и закрытую сеть. На хост опубликован только веб-интерфейс.
- Это локальный учебный запуск. TLS, Vault, кластер Kubernetes и развёртывание
  в облаке будут отдельными этапами.
