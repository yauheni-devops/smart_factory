# Frontend

Статические страницы интерфейса завода. NGINX работает от непривилегированного
пользователя, раздаёт HTML и схему, а запросы к API телеметрии проксирует по
тому же origin. Это позволяет браузеру обращаться к frontend без настройки CORS.

Главная содержит переходы в мониторинг, обслуживание, выпуск, предупреждения,
документы оборудования и отчёты. Документы — начальная структура без загрузки
файлов; отчёты показывают последние показания и позволяют скачать CSV для Excel.

NGINX проверяет сеанс через `/session` сервиса maintenance перед выдачей страниц и данных. Если сеанса нет, браузер переходит на общую форму входа, а затем возвращается на `/ui`. Для локальной проверки сначала запустите maintenance на порту 8086. Используйте одно имя хоста на всех страницах (`localhost` или `127.0.0.1`), чтобы cookie работала при переходах между портами.

На первом этапе API `telemetry` ещё запускается отдельным процессом на хосте
(порт 8082). NGINX обращается к нему через `host.docker.internal`; в Compose это
имя связано с адресом хоста. В Kubernetes входящую маршрутизацию будет выполнять
Traefik, а frontend и API станут отдельными сервисами кластера.

Контейнер frontend и Compose пока не настроены. Для текущего локального запуска
запустите `catalog` на 8081, `maintenance` на 8086 и `telemetry` на 8082, затем
откройте `http://localhost:8082/ui`. Страницы из этого каталога будут
использоваться после настройки отдельного NGINX на порту 8080.

В этой первой итерации страницы скопированы из `services/telemetry/app/static`,
а исходные файлы оставлены там для совместимости со старым адресом `/ui` на
портe 8082. После проверки переноса старую копию можно будет убрать отдельным
шагом.
