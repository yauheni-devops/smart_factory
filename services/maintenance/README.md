# Maintenance

Реестр оборудования, планы периодического технического обслуживания, наработка и заявки на работы. API работает на порту `8086`; экран `/ui` содержит сводку и отдельную вкладку «База и график ТО» с реестром оборудования и полным расписанием по регламентам. Для общих графиков и истории метрик используется Grafana + Prometheus.

На основной странице мониторинга добавлена ссылка «ПТО». Раздел ПТО и его `/api/*` защищены HTTP Basic: браузер запросит имя пользователя и пароль. Учётная запись берётся из корневого `.env` (`PTO_ACCESS_USERNAME`, `PTO_ACCESS_PASSWORD`); пароль должен содержать не менее 6 символов. `/health` и `/metrics` остаются доступны для проверок и Prometheus. Для публичного сервера используйте длинный случайный пароль (не менее 16 символов) и размещайте сервис за HTTPS reverse proxy: Basic-аутентификация без TLS не шифрует запрос.

## Запуск локальной БД

Из корня репозитория:

```bash
docker compose -f infra/docker-compose.yml up -d postgres
```

Далее:

```bash
cd services/maintenance
python -m pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8086
```

Для локального стенда скопируйте `.env.example` в `.env` и задайте пароли; файл `.env` игнорируется Git. Для публикации задайте отдельный случайный `PTO_ACCESS_PASSWORD` длиной не менее 16 символов. Сервису передайте `DATABASE_URL`, например `postgresql+psycopg://maintenance:change-this-local-password@127.0.0.1:5432/maintenance`. Не используйте локальные пароли вне лаборатории.

При первом старте сервис создаёт таблицы. После запуска `catalog` импортируйте исходный список оборудования и интервалы одной командой: `curl -X POST http://127.0.0.1:8086/api/bootstrap/catalog`. Импорт идемпотентный; существующие записи ТО не перезаписываются. Даты последнего ТО не подставляются. Для долгосрочной эксплуатации автосоздание схемы следует заменить версионируемыми миграциями Alembic.

## API

- `GET /health` — проверка API и соединения с БД.
- `GET /api/dashboard` — сводка для интерфейса.
- `POST /api/bootstrap/catalog` — первичный импорт оборудования и графиков из каталога.
- `GET/POST /api/equipment` — реестр активов.
- `GET/POST /api/plans` — планы ТО и рассчитанный статус.
- `POST /api/meter-readings` — накопительные показания счётчика (уменьшение отклоняется).
- `GET/POST /api/work-orders` — список и создание заявок на работы.
- `POST /api/work-orders/{id}/complete` — закрыть работу, сохранить факт/простой и обновить базовую дату плана.

Состояния плана: `ok`, `due_soon`, `overdue`, `unknown`. Интервал «скоро» для dashboard по умолчанию — 30 дней или 100 моточасов. Регламент обслуживания вводится ответственным на основании паспорта/утверждённых требований.

## Grafana

```bash
docker compose -f infra/docker-compose.yml up -d postgres prometheus grafana
```

Откройте `http://localhost:3000`; учётная запись и пароль задаются через `.env`. Дашборды «Завод — общий мониторинг» и «Завод — ПТО и оборудование» загружаются автоматически. Prometheus опрашивает API на портах 8081, 8082, 8083, 8085 и 8086; сами API пока запускаются на хосте. Чтобы цели были доступны Prometheus, запускайте API на `0.0.0.0`. КТП видна по телеметрии, а отдельный сервис `ktp` пока не реализован.

Метрики приложения и последние значения датчиков записываются в Prometheus. Для общей статистики узла (CPU/RAM/disk) позже потребуется Node Exporter; Grafana сама эти метрики не собирает.
